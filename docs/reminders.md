# リマインダー

指定した時刻に OS / ブラウザーの通知を出す個人用の予定。リマインダー自体はタスクリストに属さないが、オプションで通知と同時に指定したタスクリストへタスクを追加できる（「タスクリストへの追加」）。「12/3 9:00 に病院の予約を取る」のような 1 回だけのものと、「火曜と木曜の 6:30 にお弁当」「毎月第 1 月曜の 9:00 に請求書」のような繰り返しのものを扱う。繰り返しの選び方は Google カレンダーに合わせる。共有はしない。外部 API（MCP）からも作成・編集・一時停止・削除できる（[api.md](./api.md)）。

配信は 3 プラットフォームとも Cloud Functions から FCM で行い、端末内の予約通知（iOS `UNNotificationRequest` / Android `AlarmManager`）は使わない。Web には時刻指定でローカル通知を出す標準 API がなく、サーバー配信が必要になるため、全プラットフォームで同じ経路に揃える。別端末での編集は次の配信から反映される。発火時刻にオフラインの端末には、再接続後に配信期限内であれば届く。

## 画面

- タスクリスト一覧（Web の sidebar パネル / compact の一覧画面、iOS / Android の一覧・regular 幅のサイドバー）のカレンダーのナビゲーション行の下に、リマインダー画面へのナビゲーション行を置く。選択中は他の画面と同じく面色で示す。
- リマインダー画面は、追加ボタンとリマインダーの行（設定画面と同じ面カードの中に区切り線で並べる）を置く。リマインダーがなければ `reminders.empty` / `reminders.emptyHint` を表示する。行は「本文 → 時刻と繰り返し → 終了側の有効 / 一時停止のスイッチ」とし、行をタップすると編集 sheet を開く。
- 並び順は `time` の昇順、同じ時刻は `createdAt` の昇順。並び替え操作は持たない。
- 編集 sheet は上から本文（200 文字まで）、時刻と繰り返しを横に並べた行、（カスタムなら）カスタムの設定、日付の行、タスクリストへの追加の行を置く。日付は繰り返さないときはその日、繰り返すときは開始日（最初の回）になる。新規作成の初期値は今日・09:00・繰り返さない。
- 時刻は 1 分単位で、各プラットフォームの標準の時刻入力を使う（Web `<input type="time">`、iOS `DatePicker(.hourAndMinute)` の compact、Android は Material3 の `TimePicker` を dialog で開く）。12 / 24 時間表記は端末の設定に従う。繰り返しは時刻の横の残り幅に置き、長い文言は末尾を省略する（読み上げは全文）。
- 日付の行は、繰り返さないときは日付だけ、繰り返すときは `reminders.startDate` を前に付けて表示する（タスクの日付表示と同じ書式）。タップでその直下にタスクの日付設定と同じ月カレンダーを開閉する。月カレンダーは最初は閉じておき、日付を選ぶと閉じる（sheet を開いた時点で全項目が見えるようにするため）。
- 繰り返すときは、月カレンダーの表示中の月で通知する日に、カレンダー画面の色なしリストと同じ枠線だけのドットを出す。通知日の判定は「繰り返しの規則」をクライアントにも複製して行う（Functions の `reminders.ts` と揃える）。
- 繰り返しの選択肢は、選択中の日付から作る次の 8 つ（括弧内は日付が 12/1（火）の例）: 繰り返さない / 毎日 / 平日（月〜金） / 毎週（火曜日） / 毎月（1 日） / 毎月（第 1 火曜日。日付が 29 日以降なら最終火曜日） / 毎年（12 月 1 日） / カスタム。日付を変えると選択肢の曜日・日も追従する。保存済みのリマインダーを開いたときは、内容が一致する選択肢を選び、どれとも一致しなければカスタムにする。
- カスタムは、間隔（1〜99）と単位（日 / 週 / 月 / 年ごと）を選ぶ。週なら曜日のトグル（1 つ以上）、月なら「日付で（1 日）」か「曜日で（第 1 火曜日）」を選ぶ。カスタムの初期値は 1 週ごと・日付の曜日。
- タスクリストへの追加の行は、可視ラベル `reminders.addToTaskList` の下に、`reminders.addToTaskListNone`（追加しない）と参加中のタスクリスト（タスクリスト一覧の順）を選ぶ、繰り返しと同じ選択部品を置く。新規作成の初期値は追加しない。保存済みの追加先が参加中のタスクリストにない（削除・退出済み）ときは追加しないとして表示し、そのまま保存すると `taskListId: null` になる。
- 曜日の並びは月カレンダーの週開始曜日（[task-lists.md](./task-lists.md)）に合わせ、トグルは 1 行に 7 等分で並べて各言語の短い曜日名で表示し、読み上げは完全な曜日名にする。
- 終了条件（終了日・回数）は持たない（終了日の選択に 2 つ目の月カレンダーが要り、編集 sheet を圧迫するため）。止めたいときは一時停止か削除にする。
- 行の補足は「時刻 · 日付（繰り返さない）または繰り返しの説明（`reminders.repeat.*`） · 追加先のタスクリスト名（参加中のものだけ） · 状態（`reminders.ended` / `reminders.paused`）」とする。繰り返しの説明は間隔が 1 なら `daily` / `weekly` / `monthly` / `yearly`、2 以上なら `everyN*` の文言を使い、毎週の曜日が 1 つなら完全な曜日名、複数なら短い曜日名を `, ` でつなぐ。月〜金の毎週は `reminders.repeat.weekdays`。スイッチの読み上げ名は「本文, `reminders.enabled`」。
- 削除は編集 sheet 内の削除操作から確認 dialog を経て行う。行の横スワイプ・長押しメニューは持たない。
- 保存・有効切替・削除はタスク操作と同じく SDK へ投入した時点で sheet / dialog を閉じ、同期失敗はルートの `OfflineNotice` で知らせる。

## 有効 / 一時停止 / 終了

- `enabled` が `true` のリマインダーだけを配信する。スイッチで `false` にすると一時停止になり、`true` に戻すと次の該当時刻から配信を再開する。一時停止中に過ぎた回はさかのぼって送らない。
- 繰り返さないリマインダーは配信後（または配信期限切れで送らなかった後）に Functions が `enabled: false` にし、削除はしない。日時が過去の繰り返さないリマインダーは「終了」と表示し、スイッチを操作できない。「終了」の判定は端末のローカル時刻で行う。繰り返すリマインダーは起点の日付が過去でも終了にならない。
- 編集 sheet の保存は `enabled` を変更しない。ただし「終了」だったリマインダーを未来の日時へ変えるか繰り返しにして保存した場合は `enabled: true` にする。日時が過去の繰り返さないリマインダーは保存できない（保存ボタンを無効にし、`reminders.pastDateTime` を表示する）。
- 新規作成は `enabled: true` で保存する。

## 通知の許可と設定

- 設定 `notifyReminders`（既定 `false`）がオンのユーザーにだけ配信する。設定画面の通知の項目に共有リスト更新通知と並べてスイッチを置く。リマインダーがあり `notifyReminders` がオフのときは、リマインダー画面に `reminders.notificationsOff` と通知をオンにするボタンを表示する。
- リマインダーを保存したときに `notifyReminders` がオフなら、通知の許可を要求して得られた場合にオンにする。許可が得られなくてもリマインダーは保存し、設定画面のスイッチと同じエラー文言を表示する。
- 端末登録・通知許可・token 管理は共有リスト更新通知と共通（[notifications.md](./notifications.md)）。
- Android はリマインダー用の通知チャンネルを共有リスト更新通知とは別に作り、OS の設定で個別にオン / オフできるようにする。

## 通知の内容

- タイトルはアプリ名（`app.name`）、本文はリマインダーの `text`。共有リスト更新通知と異なり本文を通知に含める。
- 同じリマインダーの通知は `reminderId` で上書きし、積み上げない（Android `tag`、iOS `apns-collapse-id`、Web `tag`）。
- タップするとリマインダー画面を開く。ただしタスクを追加した回（既に追加済みだった再送を含む）は `data.taskListId` も持ち、追加先のタスクリストを開く。3 プラットフォームとも通知のタップは `taskListId` を `reminderId` より優先する（共有リスト更新通知と同じ遷移）。Web の service worker は `data.taskListId` がなく `data.reminderId` を持つ通知のクリックで、アプリタブがあれば `lightlist-open-reminders` を `postMessage` してフォーカスし、なければ `/app/#/reminders` を新しいタブで開く。
- 配信期限（FCM の TTL / `apns-expiration` / Web Push の TTL）は予定時刻から 1 時間とする。

## タスクリストへの追加

- `taskListId` が設定されたリマインダーは、配信と同じ条件（`notifyReminders` がオン、`nextFireAt` が配信期限内、本文が空でない）を満たした回に、Functions が追加先のタスクリストへタスクを追加する。端末登録の有無や FCM の配信結果には左右されない。`notifyReminders` がオフの間・配信期限切れの回・一時停止中は追加しない。
- 追加するタスクは `text` がリマインダーの本文、`date` がその回の `timeZone` における暦日、`completed` / `pinned` は `false`。入力 parser は通さない。`order` と並び順は追加先の所有者（リマインダーの所有者）の `taskInsertPosition` / `autoSort` に従い、MCP の `add_task` と同じ規則で決める。`history` には追加しない。
- 繰り返しのリマインダーは、前回追加したタスクが未完了でも毎回追加する。
- task ID は `r_<reminderId>_<nextFireAt>` とし、同じ回の重複配信で 2 件目を作らない。追加は transaction で行い、同じ ID のタスクが既にあれば書かない（完了済み・編集済みの状態を上書きしない）。
- 追加の時点で所有者が追加先の `memberKeys` にいない、または追加先がない場合は追加だけを飛ばして通知は送る。`taskListId` は書き換えない。
- 共有リストへ追加したときは、MCP と同じくリマインダーの所有者を変更者として共有リスト更新通知の処理を呼ぶ（Admin SDK の書き込みは trigger では変更者を特定できず通知しないため）。
- 追加に失敗しても通知の配信と `nextFireAt` の更新は続ける。

## 時刻の扱い

- `time` は `"HH:mm"`（24 時間制）、`date` は `"yyyy-MM-dd"` の暦日。どちらも `timeZone` の現地時刻として解釈する。
- `timeZone` は作成・編集した端末の IANA タイムゾーン名（Web `Intl.DateTimeFormat().resolvedOptions().timeZone`、iOS `TimeZone.current.identifier`、Android `ZoneId.systemDefault().id`）を書く。旅行先などで別のタイムゾーンへ移っても自動では変えず、編集して保存したときに端末の値へ更新する。MCP からの作成・編集は指定された値を書き、省略時の扱いは [api.md](./api.md) に従う。
- `repeat.weekdays` は ISO 曜日番号（1 = 月曜 … 7 = 日曜）の昇順の重複なし配列。

## 繰り返しの規則

該当日は `date` 以降の日だけとし、間隔は `date` から数える。

- `none`: `date` の 1 回だけ。
- `daily`: `date` から `interval` 日ごと。
- `weekly`: `date` を含む週（月曜始まりで数える）から `interval` 週ごとの週の、`weekdays` の曜日。
- `monthly` + `monthlyBy: "day"`: `date` の月から `interval` か月ごとの、`date` と同じ日。その日がない月（31 日に対する 30 日までの月など）は飛ばす。
- `monthly` + `monthlyBy: "weekday"`: 同じ月の数え方で、`date` の曜日の第 N 週（N は `date` の日を 7 で割って切り上げ。5 以上は最終週）。
- `yearly`: `date` の年から `interval` 年ごとの同じ月日。2 月 29 日はうるう年だけ。
- 夏時間で存在しない現地時刻は、その日の直後に存在する時刻（時刻のずれ幅だけ後ろ）で配信する。重複する現地時刻は早い方で 1 回だけ配信する。
- 次回の配信時刻 `nextFireAt` は Functions だけが計算して書く。クライアントは表示・判定に使わない。

## 配信処理（Functions）

- `reminders/{reminderId}` の書き込み trigger が、`date` / `time` / `repeat` / `timeZone` / `enabled` の変更時と作成時に `nextFireAt` を計算する。基準時刻は `updatedAt` を「現在 − 1 時間」〜「現在」に丸めた値とし、基準時刻以降の最初の該当時刻を書く（オフラインで作成・編集した内容が遅れて同期されても、配信期限内の回は送るため）。`enabled: false` なら `null`。`enabled: true` で該当時刻がない（過去の繰り返さないリマインダーなど）場合は `enabled: false` / `nextFireAt: null` にする。値が変わらないときは書き込まない。
- 毎分の scheduled Function（`* * * * *`）が `nextFireAt <= 現在 + 10 秒` のリマインダーを `nextFireAt` 昇順で最大 500 件取得し、所有者ごとに `settings` を 1 回だけ読む。`notifyReminders` がオンなら、`taskListId` があればタスクを追加してから、端末登録があれば配信し、その後に `nextFireAt` を処理した回より後の最初の該当時刻へ進め、次の回がない（繰り返さない）ものは `enabled: false` / `nextFireAt: null` にする。取りきれなかった分は次回の実行で処理する。
- 処理時点で `nextFireAt` が 1 時間以上過去のもの（Functions の停止明けなど）は配信せず、同じ手順で次の回へ進める。
- 配信してから `nextFireAt` を進める順にする（途中で失敗した場合に取りこぼすより重複配信を選ぶ。重複は `reminderId` の上書きで 1 件になる）。重複抑止用の document は持たない。
- 無効 token を示した端末登録は共有リスト更新通知と同じく削除する。
- scheduled Function は `maxInstances: 1`、retry は有効にしない。trigger は共有リスト更新通知と同じ設定とする。
- 配信またはタスクの追加をした実行だけ `reminder notification` として件数・成功件数・追加したタスク数・失敗した端末の error code を Cloud Logging に記録する。uid・token・本文・taskListId は記録しない。タスクの追加に失敗した場合は `reminder task failed` として error code だけを記録する。
- Auth ユーザーの削除時に、そのユーザーの `reminders` を削除する。

## 費用

- scheduled Function の起動は月約 43,200 回。対象がない回もクエリ 1 回分の読み取りが発生する。この固定分はユーザー数に比例しない（増えるのは配信件数に応じた読み書きだけ）ため、配信の刻みを粗くしても費用はほとんど変わらない。
- 配信 1 件あたり、所有者の `settings` の読み取り 1 回（同じ実行内の同じ所有者はまとめる）とリマインダーの書き込み 1 回。タスクリストへ追加する回は、追加先の読み取り 1 回と書き込み 1 回が加わる（共有リストなら共有リスト更新通知の分も加わる）。trigger は `nextFireAt` の書き込みで再度起動するが、計算対象の field が変わっていないため読み書きせずに終了する。
- Rules ではユーザーごとの件数を制限できないため、上限は設けず費用監視（[billing-control.md](./billing-control.md)）で扱う。
